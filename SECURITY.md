# Security and data handling

Orkhon has no account system, telemetry, credential store or network service. Opening an SSH workspace invokes the installed OpenSSH client and honors its configuration, agent and host verification. The askpass helper only returns a prompt response to the requesting SSH process; it does not save or log passwords. Private control sockets and temporary files use restricted directories.

HTML preview is an intentional browser capability: page scripts run and remote resources may load. It uses nonpersistent WebKit storage with no privileged native bridge. Only preview trusted HTML. Local pages can access file-origin resources; SSH pages can request remote files through the authenticated connection. HTML resource requests are read-only and bounded, with up to four concurrent remote reads. The built-in welcome page uses native TextKit. User Markdown previews use a separate nonpersistent WebKit view: markdown-it parses, DOMPurify sanitizes, KaTeX uses untrusted mode, and Mermaid uses strict mode. A Content Security Policy permits scripts only from bundled preview assets and blocks document scripts, event handlers, frames and network connections. Linked remote images may load when present in a document; no renderer assets are fetched from a CDN. Local and SSH Markdown image access is limited to image extensions and 16 MB per file. Document images cannot execute as scripts. Preview resources are served from a separate read-only origin. Formula expansion, diagram size/edges and cached SVG output are bounded.

The SSH event helper uses only Python’s standard library and the server’s native filesystem event API. It monitors directory entries without reading file contents, skips directory symlinks, and sends only fixed `ready`/`change` messages. The persistent channel owns its lifetime. Reconnection reconciles current state rather than assuming no changes occurred during an outage. No remote listener, daemon installation, elevated server permission, or automatic Git operation is involved.

Filesystem saves are optimistic and atomic, preserving file permissions. Conflicts keep the edited buffer intact until reviewed. Recovery snapshots contain document text and are stored with private permissions in the user's Application Support directory. They are not an encrypted backup.

For a suspected security or data-loss defect, contact the maintainer through the repository's private vulnerability-reporting channel when one is available. Include a minimal synthetic reproduction, macOS version and build revision. Do not post passwords, private keys or personal documents in public issues.
